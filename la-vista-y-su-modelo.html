    4. La vista y su modelo

    Hasta ahora, las acciones han generado sus propias respuestas. En una aplicación MVC, este es el papel de una vista: un archivo que describe la página HTML, con marcadores de posición para los datos que le pasa la acción —el modelo de la vista. [ASP.NET Core MVC] usa el motor de vistas [Razor]: una vista es un archivo [.cshtml], derivado de HTML, en el que se inserta código [C#] precedido por el carácter [@]. [Razor] forma parte del framework: no hay nada que instalar.

    using Example13.Models;
using Microsoft.AspNetCore.Mvc;

namespace Example13.Controllers;

public class ViewsController : Controller
{
    // View(model): la vista que lleva el nombre de la acción (Views/Views/Index.cshtml)
    [HttpGet("/")]
    public IActionResult Index()
    {
        var model = new PageModel(
            "My first view",
            "This page was built by Razor, on the server.",
            DateTime.Now.ToString("HH:mm:ss"));
        return View(model);
    }

    // View(name, model): la vista la elige la acción
    [HttpGet("hello/{name}")]
    public IActionResult Hello(string name)
    {
        if (name == "unknown")
        {
            Response.StatusCode = 404;
            return View("Unknown", name);
        }
        var model = new PageModel(
            $"Hello {name}",
            "This time, the action designated the view by its name.",
            DateTime.Now.ToString("HH:mm:ss"));
        return View("Index", model);
    }
}

    Comentemos este código:

    • línea 6: el controlador deriva de la clase [Controller], en lugar de [ControllerBase]: [Controller] agrega a [ControllerBase] todo lo relacionado con las vistas (los métodos [View], [ViewData], [TempData], etc.);
    • líneas 12–15: la acción genera el modelo de la vista: un título, un mensaje y la hora actual;
    • línea 16: [View(model)] devuelve un [ViewResult]: la acción ya no genera la respuesta; en su lugar, designa una vista y le pasa un modelo. Si no se especifica ningún nombre de vista, se usa la vista con el mismo nombre que la acción: [Index];
    • líneas 23–26: cuando la vista depende de la solicitud, la acción elige la vista. Aquí, el nombre [unknown] muestra la vista [Unknown], con código de estado 404. El modelo de esta vista es una simple cadena;
    • línea 32: la acción [Hello] especifica explícitamente la vista [Index] por su nombre: dos acciones comparten la misma vista, con modelos diferentes.

    • [Views/Views/Index.cshtml]: la carpeta que lleva el nombre del controlador (sin el sufijo [Controller]);
    • [Views/Shared/Index.cshtml]: la carpeta que contiene las vistas compartidas por todos los controladores (véase el ejemplo 15).

    Comentemos este código:

    • líneas 2–5: un bloque de código [@{ ... }] contiene instrucciones [C#]. No produce nada en la página. Las variables que declara ([total], [count]) pueden usarse más adelante en la vista;
    • línea 16: un valor [null] ([@Model.Nickname]) no muestra nada, sin ningún error;
    • líneas 18–19: una expresión [@...] escapa los caracteres especiales de HTML ([<] se convierte en [&lt;]...): el texto se muestra tal cual. [@Html.Raw(...)] lo inserta sin escapar: se interpreta como HTML. [Html.Raw] solo se usa para HTML generado por la aplicación, nunca para datos introducidos por un usuario: este podría inyectar HTML, e incluso [JavaScript], en la página (un ataque conocido como [XSS], [cross-site scripting]);
    • líneas 21–27: una condición. Después de [@if (...)], el contenido entre llaves es HTML: [Razor] reconoce el inicio de una etiqueta y vuelve al modo HTML. Regresamos a [C#] mediante [@];
    • líneas 32–40: un bucle [for] de [C#]. [var product = ...] es una instrucción [C#], [<li>] es de HTML: [Razor] alterna entre ambos sin ningún marcador específico;
    • línea 36: una expresión explícita [@( ... )]. Los paréntesis son obligatorios siempre que la expresión contenga espacios u operadores (en este caso, el operador condicional [? :]);
    • línea 37: para escribir texto sin formato dentro de un bloque [C#], enciérrelo en la etiqueta especial [<text>], que no aparece en la página;
    • línea 38: [@:] hace lo mismo para el resto de la línea;
    • líneas 45–51: una lista vacía es simplemente un [if]. En el bloque [else], que ya está en modo [C#], [foreach] se escribe sin [@];
    • línea 55: las variables del bloque [@{ }] y las expresiones explícitas, incluida una llamada a un método: [ToString("0.00")] formatea un número con dos decimales;
    • línea 56: una ruta con puntos [@Model.Address.Street] y una llamada a un método [ToUpper()];
    • línea 57: [Razor] reconoce que una [@] colocada entre dos caracteres alfanuméricos no es código: [contact@example.com] es una dirección de correo electrónico. Para escribir una [@] que sería ambigua, se duplica: [@@].

using System.Text.Unicode;
using Microsoft.Extensions.FileProviders;

var builder = WebApplication.CreateBuilder(args);

var app = builder.Build();

    Comentemos este código:

    • línea 9: el servicio [HtmlEncoder] es el que utiliza [Razor] para escapar las expresiones en [@]. De forma predeterminada, solo deja pasar los caracteres del alfabeto latino básico: por eso [é] se codifica como [&#xE9;] (y [€] como [&#x20AC;]). Reemplazamos este servicio por un codificador que deja pasar todos los caracteres ([UnicodeRanges.All]). Los caracteres peligrosos ([<], [>], [&], ["], [']) siguen escapados: la protección contra la inyección de HTML permanece intacta. Todos los ejemplos siguientes, así como el caso de estudio, incluyen esta línea;
    • línea 14: un componente de middleware (véase el capítulo 7) que sirve los archivos de la carpeta [wwwroot] del proyecto: el archivo [wwwroot/css/styles.css] se sirve en la URL [/css/styles.css]. Si el archivo no existe, la solicitud continúa hacia los controladores;
    • líneas 16–19: un segundo servicio de archivos estáticos. El framework CSS [Bootstrap] es común a todos los ejemplos: se almacena una sola vez, en la carpeta [examples/common/bootstrap], y se sirve bajo el prefijo [/bootstrap]. [PhysicalFileProvider] designa una carpeta del disco; [ContentRootPath] es la carpeta del proyecto. Así, [examples/common/bootstrap/css/bootstrap.min.css] se sirve en la URL [/bootstrap/css/bootstrap.min.css]. El caso de estudio, en cambio, coloca [Bootstrap] en su propia carpeta [wwwroot].

// funciones C# ordinarias, invocables desde las vistas: @Formats.Money(...)
public static class Formats
{

    public static string Uppercase(string? text) => (text ?? "").ToUpperInvariant();

    // un monto en una moneda, en el formato del idioma actual (CultureInfo.CurrentCulture)
    // "C" = moneda; el objeto NumberFormatInfo define el símbolo monetario
    public static string Money(decimal amount, string currency = "EUR")
    {
        var format = (NumberFormatInfo)CultureInfo.CurrentCulture.NumberFormat.Clone();
        format.CurrencySymbol = currency == "USD" ? "$" : "€";
        return amount.ToString("C", format);
    }

    // una fecha en palabras completas, en el idioma actual: "Wednesday, September 23, 2026"

    // un helper que construye HTML: devuelve un IHtmlContent, que Razor no escapa.
    // Entonces le corresponde al helper escapar los datos que inserta (HtmlEncoder)
    public static IHtmlContent Badge(int stock)
    {
        var cssClass = stock > 0 ? "text-bg-success" : "text-bg-danger";
        var text = HtmlEncoder.Default.Encode(stock > 0 ? $"{stock} in stock" : "sold out");
        return new HtmlString($"<span class=\"badge {cssClass}\">{text}</span>");
    }
}

namespace Example16.TagHelpers;

// un Tag Helper: se aplica a las etiquetas <a> que llevan el atributo "active-path"
// <a href="/products" active-path="/products"> recibe la clase "active" si la
// página actual está bajo esta ruta
[HtmlTargetElement("a", Attributes = "active-path")]
public class ActiveTagHelper(IHttpContextAccessor accessor) : TagHelper
{
    // el valor del atributo active-path="..."
    public string ActivePath { get; set; } = "";

    public override void Process(TagHelperContext context, TagHelperOutput output)
    {
        var path = accessor.HttpContext?.Request.Path.Value ?? "/";
        var isActive = ActivePath == "/" ? path == "/" : path.StartsWith(ActivePath, StringComparison.Ordinal);
        if (isActive)
        {
            output.AddClass("active", HtmlEncoder.Default); // agrega la clase al atributo class
        }
    }
}

    4.7.1. Validación por el navegador

    Los atributos [required], [maxlength], [min], [max], [type="email"]... indican al navegador que valide el formulario antes de enviarlo: el usuario recibe un aviso inmediato mediante un globo de ayuda, sin ningún intercambio con el servidor.     4.8. Ejemplo 20: el patrón Post/Redirect/Get

    Cuando un formulario POST se envía con éxito, la acción puede mostrar directamente una página. El problema surge si el usuario actualiza luego esa página (tecla F5): el navegador reenvía el formulario y la operación se realiza por segunda vez (un pedido hecho dos veces, una cita agendada dos veces...). El patrón Post / Redirect / Get (PRG) evita este problema: una acción POST exitosa no genera una página; en su lugar, redirige a una página GET. Volver a cargar esta página solo desencadena otro GET, sin efecto alguno.

    Queda un detalle: la página GET debe mostrar un mensaje (“la tarea ha sido agregada”), aunque este mensaje lo haya generado la acción POST en otra solicitud. Para resolverlo, [ASP.NET Core] ofrece [TempData]: un diccionario cuyo contenido persiste hasta la siguiente solicitud y desaparece en cuanto se lee. Es un mensaje flash. De forma predeterminada, [TempData] se almacena en una cookie cifrada por el servidor.

    [
        new(1, "Marie Durand", "01 23 45 67 89"),
        new(2, "Paul Martin", "06 12 34 56 78"),
        new(3, "Philippe Jandot", "02 98 76 54 32"),
    ];

    // null si el contacto no existe
    public Contact? Read(int id) => contacts.Find(c => c.Id == id);

    public Contact? Edit(int id, string name, string phone)
    {
        var index = contacts.FindIndex(c => c.Id == id);
        if (index < 0) return null;
        // un record es inmutable: lo reemplazamos por una copia modificada (con with)
        contacts[index] = contacts[index] with { Name = name, Phone = phone };
        return contacts[index];
    }

    public Contact Add(string name, string phone)
    {
        var contact = new Contact(++lastId, name, phone);
        contacts.Add(contact);
        return contact;
    }

    public Contact? Delete(int id)
    {
        var contact = Read(id);
        if (contact is not null) contacts.Remove(contact);
        return contact;
    }
}

    // confirmación de los formularios que llevan el atributo data-confirmation="..."
// Sin JavaScript, estos formularios simplemente se envían sin confirmación.
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // el formulario que se enviará si el usuario confirma

  // 1. interceptamos el envío de los formularios que requieren confirmación
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // el envío queda suspendido
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // aparece la ventana
    });
  });

  // 2. los dos botones de la ventana
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // envío, SIN disparar de nuevo el evento 'submit'
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • línea 3: el código está envuelto en una función que se ejecuta inmediatamente, para evitar crear variables globales;
    • líneas 9–14: se intercepta el envío de cada formulario que tiene el atributo [data-confirmation]. [preventDefault()] suspende el envío; se guarda el formulario, se coloca la pregunta en la ventana ([textContent], no [innerHTML]: la pregunta se muestra como texto, nunca se interpreta como HTML) y se muestra la ventana;
    • Líneas 19–25: “Yes” envía el formulario guardado. El método [submit()] de un formulario lo envía sin desencadenar el evento [submit]: no hay una nueva solicitud de confirmación. “No” oculta la ventana.

    Si [JavaScript] está desactivado, los formularios simplemente se envían sin confirmación: la aplicación sigue funcionando. Este es el principio de mejora progresiva: [JavaScript] aporta comodidad, pero no es esencial.
