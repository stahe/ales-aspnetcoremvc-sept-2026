    Este documento es obra de Claude, la IA de Anthropic. Sigue al documento “Introducción paso a paso al framework web [NestJS]” (2026), que a su vez adaptó el documento “Introducción a ASP.NET MVC mediante ejemplos” (2013) al framework [NestJS]. Este documento recorre el camino inverso y regresa a la plataforma [.NET], en su versión actual:

    • el framework [NestJS] y el lenguaje [TypeScript] se sustituyen por el framework [ASP.NET Core MVC] y el lenguaje [C#];
    • las vistas [Handlebars] se sustituyen por vistas [Razor];
    • el ORM [TypeORM] se sustituye por el ORM [Entity Framework Core], siempre sobre [MySQL].

    El documento sigue de cerca la progresión del curso de [NestJS]: primero, numerosos proyectos pequeños, cada uno centrado en un solo concepto, y luego un caso de estudio completo —una aplicación web para la gestión de citas en un consultorio médico— con todos los archivos comentados en detalle. Los ejemplos tienen los mismos números y tratan los mismos temas que en el curso de [NestJS]: un lector que conozca ese curso puede comparar los dos frameworks ejemplo por ejemplo. Sin embargo, esto no es necesario: este documento se basta a sí mismo y no supone ningún conocimiento previo de [NestJS] ni, para el caso, de [ASP.NET]. Los únicos requisitos previos son una comprensión básica de la programación web (el protocolo HTTP, el lenguaje HTML) y el lenguaje [C#].

    1.1. El papel de ASP.NET Core MVC en una aplicación web

    Una aplicación web suele construirse en capas, y cada capa se comunica solo con las capas vecinas:

    • la capa web recibe las solicitudes HTTP del navegador y le devuelve páginas HTML. Es la capa que [ASP.NET Core MVC] nos ayuda a escribir;
    • La capa de negocio contiene las reglas de negocio de la aplicación (por ejemplo, “un paciente solo puede tener una cita próxima”). No sabe nada de la web: podría servir igualmente a una aplicación de línea de comandos;
    • La capa de acceso a datos (capa [DAO], por [Data Access Object]) lee y escribe en la base de datos. Usaremos el ORM [Entity Framework Core] ([Object Relational Mapper]), que establece la correspondencia entre las filas de las tablas y los objetos en [C#].

    La propia capa web sigue el modelo [MVC] ([Model – View – Controller]):

    • el controlador (C) es una clase cuyos métodos —llamados acciones— se encargan cada uno de un tipo específico de solicitud (por ejemplo, [GET /schedule]). Una acción lee los parámetros de la solicitud, invoca la capa de negocio y luego elige la vista que se mostrará;
    • el modelo (M) es el conjunto de datos que la acción pasa a la vista: un objeto [C#];
    • la vista (V) es un archivo [Razor] (extensión [.cshtml]): a partir de HTML, en el que las expresiones [C#] —precedidas por el carácter [@]— se reemplazan por datos del modelo.

    El procesamiento de una solicitud sigue los pasos numerados del diagrama:

    • 1: El navegador envía una solicitud HTTP, por ejemplo, [GET /schedule?doctorId=1&day=2026-09-24];
    • 2: El servidor web [Kestrel], integrado con [ASP.NET Core], recibe la solicitud. Esta pasa por una serie de componentes de middleware (lectura de cookies, autenticación, archivos estáticos, etc.) y luego [ASP.NET Core] selecciona la acción encargada de procesar esta solicitud: esto es el enrutamiento. Antes de llegar a la acción, la solicitud aún puede pasar por filtros, que exploraremos en capítulos posteriores;
    • 3: La acción solicita a la capa de negocio los datos que necesita;
    • 4: Construye el modelo de la vista y designa la vista que debe mostrarlo;
    • 5: El motor de vistas [Razor] genera la página HTML, que [ASP.NET Core] devuelve al navegador.

    [ASP.NET Core] es el framework web de la plataforma [.NET] de Microsoft. Gratuito y de código abierto, se ejecuta en [Windows], [Linux], y [macOS]. Permite crear servidores que devuelven JSON a un cliente [JavaScript] ([Angular], [React], [Flutter]...) así como aplicaciones web tradicionales, en las que el servidor genera las páginas HTML y el navegador se limita a mostrarlas. Es este segundo caso de uso —la parte MVC del framework— el que estudia este documento. Al igual que [NestJS], que se inspiró mucho en él, [ASP.NET Core] se basa en dos ideas: los atributos ([[HttpGet]], [[Route]], [[Authorize]]...) describen los roles de las clases y los métodos, y la inyección de dependencias proporciona a cada objeto las dependencias que necesita.

    1.2. Herramientas utilizadas

    Los ejemplos se escribieron y probaron con las siguientes herramientas (su instalación se describe en el apéndice):

    • el SDK de [.NET] 10 ([Software Development Kit]), que contiene el compilador de [C#], el framework [ASP.NET Core] y la herramienta de línea de comandos [dotnet]. [.NET] 10 es la versión LTS (Long-Term Support) actual;
    • el editor [Visual Studio Code], con la extensión [C# Dev Kit];
    • un navegador reciente ([Chrome], [Firefox], [Edge]);
    • la herramienta de línea de comandos [curl], que muestra las respuestas HTTP sin procesar (viene incluida con [Windows] 10 y 11);
    • el SGBD [MySQL] (o [MariaDB]), por ejemplo, el de [Laragon] en [Windows], a partir del capítulo sobre el acceso a datos y para el caso de estudio.

    El framework [ASP.NET Core] forma parte del SDK: los ejemplos no requieren ninguna biblioteca adicional hasta el capítulo 8. Los ejemplos 25 a 28 y el caso de estudio usan tres bibliotecas, que se descargan automáticamente del sitio [nuget.org] durante su primera compilación (por lo que ese día debe estar conectado a Internet): [Microsoft.AspNetCore.Authentication.JwtBearer] (tokens JWT), [BCrypt.Net-Next] (hashes de contraseñas) y [Pomelo.EntityFrameworkCore.MySql] ([Entity Framework Core] para [MySQL]).

    1.3. Ejecutar el caso de estudio

    Nota del revisor: Aconsejo al lector que realice el caso de estudio de inmediato, como se describe a continuación. Una vez que haya comprendido bien el papel de esta aplicación de gestión de citas, pida a su IA favorita que modifique la aplicación de la siguiente manera: a partir de ahora, cada médico podrá:

    • definir sus propios horarios de citas entre dos fechas. Esto les permitirá ajustar su agenda según sus necesidades;
    • quitar ciertos horarios del calendario en un día determinado —por ejemplo, si no están disponibles por motivos personales;

    La modificación no es trivial, porque implica un cambio en la estructura de la base de datos. Pida a la IA que le entregue el nuevo código de la aplicación y el script SQL para crear la nueva base de datos. Para ello, deberá proporcionarle el archivo ZIP con el proyecto completo, así como el script SQL de la base de datos anterior.

    Además, no he revisado el curso creado por Claude. Él ya había producido un curso de [NestJS] perfecto. Supuse que lo mismo ocurriría con este. Si tiene algún problema para entender algo, la solución es siempre la misma: pida a su IA favorita que le explique lo que no entiende. Claude, por ejemplo, es muy bueno para esto. Quizá deba “subirle” el ejemplo que no entiende.

    Para ejecutar un ejemplo, abra una terminal en su carpeta (en [Visual Studio Code]: haga clic con el botón derecho en la carpeta del ejemplo y luego seleccione “Abrir en la terminal integrada”) y escriba:

    1
    dotnet run

    [dotnet run] compila el proyecto (en su carpeta [bin]), y luego ejecuta la aplicación. Con [dotnet watch], el código se recompila y la aplicación se reinicia cada vez que se modifica un archivo [.cs] o [.cshtml]:

    1
    dotnet watch

    Todos los ejemplos escuchan en el puerto 5000, el puerto predeterminado de [ASP.NET Core]: solo uno puede estar en ejecución a la vez. Detenga el servidor con [Ctrl-C] en la terminal. También puede compilar todos los ejemplos a la vez desde la carpeta [examples] para verificar que la instalación esté completa:

    1
    dotnet build examples.slnx

    Veamos este archivo:

    • línea 9: la versión objetivo de [.NET]: [.NET] 10;
    • línea 11: los tipos de referencia “anulables” (nullable). El compilador distingue entre una variable de tipo [string], a la que nunca se debe asignar el valor [null], y una variable de tipo [string?], a la que sí se le puede asignar ese valor, y emite una advertencia ante cualquier posible error que involucre [NullReferenceException];
    • Línea 13: Los espacios de nombres más comunes ([System], [System.Linq], [System.Threading.Tasks], [Microsoft.AspNetCore.Builder]...) se importan automáticamente en cada archivo: no es necesario escribir las directivas [using] correspondientes.
